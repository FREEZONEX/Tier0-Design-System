# 01-tokens

设计系统的唯一真源。所有颜色、字体、间距、圆角、动效的值只在这里定义。

只有颜色分两层：`base.json` 定义色值（品牌色 + 产品色），`light.json` / `dark.json` 按用途映射到浅色和深色主题。其他类别不随主题变化，每类一个文件。

| 文件 | 内容 | 状态 |
|---|---|---|
| `color/base.json` | 品牌色（5 个）、色阶（绿、黑、灰）、辅助色（8 个色相） | 已定 |
| `color/light.json` | 浅色主题：主层 18 个（表面与文字、品牌、状态）+ 产品扩展 | 已定 |
| `color/dark.json` | 深色主题：同上 | 已定 |
| `typography.json` | 字体、字重、字阶（11 级） | 已定 |
| `spacing.json` | 间距刻度、按用途的间距、控件与行高 | 初稿 |
| `radius.json` | 圆角：4px 为主，卡片 6px，上限 8px，圆形元素例外 | 初稿 |
| `border.json` | 线宽与线型 | 初稿 |
| `shadow.json` | 阴影：只用于浮层与交互反馈 | 初稿 |
| `motion.json` | 时长、曲线 | 初稿 |
| `layout.json` | 断点、页面结构、栅格、内容宽度 | 初稿 |

格式采用 W3C Design Tokens（DTCG）。用途映射里的每个 token 都要写明用在哪、不用在哪。

CSS、Tailwind、Figma 变量等成品文件不放在仓库里，需要时由脚本在构建时生成。

命名与前端 `packages/theme` 保持一致，不另起一套。

## 颜色用途 token

组件只使用 `light.json` / `dark.json` 主层的语义名称，不直接使用色阶。

**表面与文字**

| Token | 用途 |
|---|---|
| `background` | 页面底色 |
| `foreground` | 正文与标题 |
| `card` | 实色表面：面板、弹窗、产品界面截图的容器 |
| `subtle` | 大面积分区底色：卡片区、表格区 |
| `muted` | 悬停填充、行内代码、输入框底 |
| `muted-foreground` | 说明、次要标签、时间戳 |
| `border` | 单元格之间、卡片周围的细线 |
| `input` | 输入框、选择器等交互控件的边框 |

**品牌**：品牌绿只承担两种角色：信号（运行、实时数据、选中）和品牌面（重点区块的绿色块或浅绿底），每个区域只有一个品牌绿实色焦点，浅绿底不受此限。

| Token | 用途 |
|---|---|
| `primary` | 唯一的主操作 |
| `primary-foreground` | 主操作上的文字 |
| `highlight` | 品牌绿：信号、实时数据、选中、重点区块 |
| `highlight-foreground` | 品牌绿底上的文字 |
| `highlight-deep` | 深绿：Logo、品牌图形和大面积的绿色识别 |
| `highlight-ink` | 绿色的文字和图标 |
| `accent` | 选中行、高亮行的浅绿底 |
| `ring` | 键盘焦点环，宽 2px |

**状态**：只用于真实的结果，并且总是配合图标或文字，不只依赖颜色。辅助色只用于图表和分类标签。

| Token | 用途 |
|---|---|
| `success` | 已完成、已保存、已连接 |
| `warning` | 需要注意、接近上限 |
| `destructive` | 破坏性操作和错误 |
| `info` | 中性提示及提示中的链接 |

**品牌绿怎么出现**

判断标准是这个元素需不需要阅读和辨认：

- **装饰性的简单形状**，如装饰圆点、方块、箭头、进度条、色块，可以直接用品牌绿 `#B2ED1D`。作为填充色时，上面的文字用近黑 `#050B14`。
- **需要识别含义的状态圆点**（运行 / 在线等），在浅色背景上用 `highlight-ink`，不加描边：品牌绿在白底上只有 1.40:1，看不清；`highlight-ink` 为 6.71:1。
- **需要阅读和辨认的元素**，如文字、图标，用 `highlight-ink`（浅色模式为 `#4B640C`），保证在白底上清晰可读。
- 深绿 `#73B200`（`highlight-deep`）用于 Logo、品牌图形和大面积的绿色识别。

**规则**

1. 组件只使用 `light.json` / `dark.json` 主层的 token，不直接使用 `base.json` 的色值。
2. 使用语义工具类：`bg-background`、`text-muted-foreground`、`border-border`。
3. 组件中不写物理颜色：不用 `#fff`、`gray-500`、`bg-white`。
4. 组件中不写 `dark:` 分支。深色模式由 `.dark` 类和 token 层负责。
5. 页面不用彩色大面积背景；白底上需要阅读或辨认的绿色（文字、图标、表达状态的圆点）使用 `highlight-ink`。
6. 不用渐变、玻璃质感、渐变文字、渐变描边或大面积色彩晕染。
7. 次要文字（`muted-foreground`）不放在 `muted` 背景上（对比度 4.27:1）；`muted` 背景上的文字用 `foreground`。

`extended` 分组是前端现有的细分 token（如 `bg-secondary`、`success-tertiary`），保留用于兼容，新组件优先使用主层。

## 字体

| 用途 | 字体 | Token |
|---|---|---|
| 标题 | Inter | `font.family.display` |
| 正文与界面文字 | IBM Plex Sans | `font.family.sans` |
| 代码、数据路径、数值 | IBM Plex Mono | `font.family.mono` |
| 中文 | 系统字体：苹方 / 微软雅黑 | `font.family.sc`（作为以上三种的中文回落） |
| Logo 字标 | Tektur | `font.family.logo`（仅 Logo，交付时转为路径） |

中文使用系统字体，不加载中文 Web 字体：中文字体单个字重就有数 MB，在工厂内网、私有化部署和弱网环境下会明显拖慢首屏，离线部署时还可能加载失败；苹方和微软雅黑覆盖绝大多数办公与工控终端，屏幕显示清晰，气质与 IBM Plex Sans 接近。

前端的 Tailwind `font-sans` 应指向 `--font-app-sans`（IBM Plex Sans），不使用 Geist。

**字阶**

字阶分两套：**产品字阶**用于产品后台，与前端 `packages/theme/src/tailwind.css` 一致；**官网字阶**用于官网、Deck 和宣传物料，与官网现状一致。每个 token 的前端对应写在 `typography.json` 的 `$extensions.tier0.frontend` 里。

*产品字阶*（`typography.product`）

| Token | 字体 | 字号 / 行高 | 字重 | 用途 |
|---|---|---|---|---|
| `typo-h1` | Inter | 38 / 46 | 700 | 页面大标题 |
| `typo-h2` | Inter | 30 / 36 | 600 | 产品页面标题（text-3xl font-semibold）、官网分区标题 |
| `typo-h3` | Inter | 24 / 32 | 600 | 弹窗标题、子标题 |
| `typo-h4` | Inter | 20 / 28 | 500 | 面板、卡片标题 |
| `body-lg` | IBM Plex Sans | 18 / 28 | 400 | 引导语、空状态说明 |
| `body` | IBM Plex Sans | 16 / 24 | 400 | 长段落；中文长文行高放宽到 28 |
| `body-sm` | IBM Plex Sans | 14 / 20 | 400 | 产品界面正文（默认） |
| `label` | IBM Plex Sans | 14 / 20 | 500 | 按钮、表单标签、导航 |
| `caption` | IBM Plex Sans | 12 / 16 | 400 | 辅助说明、时间戳 |
| `title` | IBM Plex Sans | 12 / 16 | 500 | 全大写分组小标题，仅英文 |
| `code` | IBM Plex Mono | 13 / 20 | 400 | 代码、命令行、数据路径、实时读数 |

*官网字阶*（`typography.web`）

标题、正文、说明、代码与产品字阶相同，另有下面三级：

| Token | 字体 | 字号 / 行高 | 字重 | 用途 |
|---|---|---|---|---|
| `display` | Inter | 48 / 60 | 500 | 官网首屏、Deck 封面，每页最多一次；产品界面不用 |
| `label` | IBM Plex Mono | 14 / 20 | 500 | 导航、按钮、链接；按钮文字可全大写 |
| `title` | IBM Plex Mono | 12 / 16 | 400 | 分组小标签，全大写，用斜杠分隔层级，如 `EDGE_DATA / INDEPENDENT SOURCES` |

**规则**

1. 标题用 Inter，正文用 IBM Plex Sans，代码、数据路径与实时读数用 IBM Plex Mono；中文使用系统字体（苹方 / 微软雅黑）；Tektur 只用于 Logo。
2. 不引入以上之外的字体。
3. 中文标题和中英混排标题字距为 0；只有纯英文标题使用字阶里的负字距。
4. 建议最小字号 12px；更小的字号只用于图表刻度等不需要阅读的文字。
5. 字重只用 400 / 500 / 600 / 700。
6. 实时读数、数据路径、代码用 code 字阶（IBM Plex Mono）；表格里的数字用正文字体并开启等宽数字（tabular-nums）。
7. 只用字阶里的字号，不写任意值（如 text-[17px]）。前端现有写法对应：text-lg → body-lg，text-xl → typo-h4，text-2xl → typo-h3，text-[13px] → code，text-[17px] → body-lg。
8. 段落之间：body-sm 正文间隔 12px，body 正文间隔 16px（见 spacing.json）。
9. 连续的中文长文（文档、帮助）使用 body，行高放宽到 28px。
10. 截断：表格单元格、标签、导航单行截断加省略号，并能查看完整内容；卡片说明最多 2 行。
11. 文字颜色：标题与正文用 foreground；说明、时间戳用 muted-foreground；绿色文字用 highlight-ink。次要文字不放在 muted 背景上（对比度 4.27:1，低于 4.5:1）。
12. 不用斜体做强调。

## 间距与布局

间距和布局决定信息层级：同一层级用同一档间距，层级越高间距越大；页面内的层级用间距和 1px 细线区分，阴影只用于浮层和交互反馈（见下文「阴影」）。所有数值与前端 `packages/ui` 组件和 Tailwind 默认刻度一致，每一项的依据写在 JSON 的 `$extensions.tier0.rationale` 里。

**间距刻度**（`spacing.json` → `space`，4px 基准）

| Token | 值 | 用途 | 前端 |
|---|---|---|---|
| `space.1` | 4px | 图标与紧贴文字、徽标内边距 | `gap-1` |
| `space.1-5` | 6px | 仅控件内部：按钮、Tab 内的图标与文字 | `gap-1.5` |
| `space.2` | 8px | 组内：同组控件、标签与输入框、列表项 | `gap-2` |
| `space.3` | 12px | 输入类控件水平内边距、表单项之间 | `px-3` |
| `space.4` | 16px | 组间：卡片之间、按钮水平内边距、移动端页边距 | `gap-4` `px-4` |
| `space.6` | 24px | 卡片与面板内边距、桌面栅格沟槽与页边距 | `p-6` `gap-6` |
| `space.8` | 32px | 弹窗内边距、页面内大区块之间 | `p-8` `gap-8` |
| `space.12` | 48px | 产品页面的分区之间 | `gap-12` |
| `space.16` / `space.24` | 64 / 96px | 文档与官网的章节之间 | — |

**层级与间距的对应**

| 层级 | 间距 | 例子 |
|---|---|---|
| 元素内 | 4–6px | 图标 + 文字 |
| 组内 | 8px | 标签 + 输入框；按钮组 |
| 组与组 | 16px | 表单的两组字段；并排的卡片 |
| 区块内边距 | 24px | 卡片、面板 |
| 区块与区块 | 32–48px | 页面里的两个分区 |

**控件与行高**（`spacing.json` → `size`）

| Token | 值 | 用在 |
|---|---|---|
| `control-sm` | 32px | 按钮默认、工具栏（产品界面默认） |
| `control-md` | 36px | 输入框、选择器、标签页 |
| `control-lg` | 40px | 页面主操作、登录与引导 |
| `table-header` / `table-row` | 40px | 表格表头与数据行 |
| `touch` | 44px | 车间平板、触屏 HMI 的最小点击尺寸 |
| `app-header` | 64px | 产品顶部栏 |

**布局**（`layout.json`）

- 断点沿用 Tailwind 默认：640 / 768 / 1024 / 1280 / 1536。产品界面以 1280 为主设计宽度。
- 页面结构：顶部栏 64px + 侧栏 256px（收起 48px，移动端抽屉 288px）+ 内容区；内容区内边距桌面 24px、移动端 16px。
- 12 栏栅格，沟槽桌面 24px、移动端 16px。
- 连续阅读的文字单行最大 680px；表格、看板、拓扑图占满内容区，内容区最大 1440px。
- 弹窗宽度三档：确认 480px、表单 672px、带表格或预览 1024px。

**规则**

1. 间距、内边距和组件尺寸只取上表档位；2px 只用于图标与文字的微调。
2. 进入更高一层级时，间距至少升一档。
3. 页面内的层级用间距和 1px 细线区分，不加额外底色；阴影只用于浮层和交互反馈。
4. 产品界面默认紧凑密度（控件 32px、行高 40px、卡片内边距 24px），同一页面不混用两种密度。
5. 监控看板按「概览 → 列表 → 详情」排列：关键读数在首屏左上，告警紧挨读数，明细在下方。
6. 1024px 以下侧栏改为抽屉；768px 以下表格改为卡片列表或横向滚动，不把列宽压到无法阅读。
7. 车间平板、触屏终端上的可点击元素不小于 44px。

## 圆角、线宽、阴影、动效

**圆角**（`radius.json`）：以 4px 为主，接近直角。

| Token | 值 | 用在 |
|---|---|---|
| `md` | 4px | 默认：按钮、输入框、选择器、标签、弹窗、下拉 |
| `lg` | 6px | 卡片、面板、侧滑面板 |
| `xl` | 8px | 上限：截图、视频、插图等媒体容器 |
| `sm` | 2px | 标签内小元素、色块 |
| `full` | 全圆 | 例外：胶囊徽章、进度条、开关、滑块、头像、状态圆点 |

前端 `card` 当前为 10px（`rounded-xl`），按本规范应为 6px（`rounded-lg`）。

**线宽**（`border.json`）：分隔、外框、行线、输入框统一 1px；2px 只用于焦点环、选中指示和图表强调线；虚线只表示尚未存在的对象（新建占位、拖放区、草稿连线）。

**阴影**（`shadow.json`）：界面的气质以细线为主，页面内的卡片、面板、表格不用阴影。阴影只在两种情况出现：

| Token | 用在 | 原因 |
|---|---|---|
| `xs` | 按钮、输入框 | 交互反馈：提示可以按下，强度低到不破坏扁平感 |
| `md` | 下拉、气泡、提示、通知；拖拽中的元素 | 浮层：说明它在内容之上；拖拽时表示被「拿起」 |
| `lg` | 弹窗、侧滑面板 | 浮层：离页面最远的一层，集中注意力 |

深色模式下阴影看不见，浮层改用 1px `border` 区分。

**动效**（`motion.json`）：动效用来说明状态变化和层级关系。

| Token | 值 | 用在 |
|---|---|---|
| `duration.fast` | 150ms | 悬停、按下、颜色变化 |
| `duration.base` | 200ms | 下拉、弹窗、提示的出现和消失 |
| `duration.slow` | 300ms | 侧滑面板、抽屉、页面区块切换 |
| `duration.signal` | 2000ms | 运行指示灯的呼吸周期 |
| `easing.enter` / `exit` / `standard` | ease-out / ease-in / ease-in-out | 进入 / 退出 / 其余 |

不用回弹和弹性曲线；实时数据直接替换，不做数字滚动；同一视图只有一个持续循环的动效；系统开启「减少动态效果」时过渡改为 0ms，循环停止。
