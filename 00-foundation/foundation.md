# Tier0 Foundation

设计系统的起点。Token、组件、品牌物料和 AI 规则都从这份文档出发；当具体规范与本文冲突时，以本文为准。

## 1. 品牌故事

### Tier0 是什么

Tier0 为 **制造业** 构建 **Agentic 工业数据平台**。

它让工厂设备和业务系统的数据只需接入一次，就能被语义化集成；让 AI Agent 能在这层数据之上持续地分析、执行和生成应用。

> **Connect once, Reuse everywhere.**

### 故事

每一座工厂里，都有成千上万台设备在不停地产生数据。但这些数据散落在 PLC、MES、ERP 和各种系统里，彼此不通。每做一个新应用，都要重新接一遍；每用一次 AI，都要先花几个月整理数据。

Tier0 把工厂的设备和系统一次接入：来自设备的时序数据，和来自 MES、ERP 等业务系统与应用的业务数据，都按工厂、区域、设备、工序、工单统一组织起来，让每一个数据点都有名字、有位置、有来源、有语义关系。

于是，整座工厂的业务、数据、设备都可以被放进一个平台里。在这个平台上，AI Agent 开始工作：它看得懂工厂，会持续地分析、预警、执行，并生成工厂真正需要的应用。

### 为什么重要

- 没有客户会把整座工厂的数据交给一个看起来不稳定的东西。Tier0 的品牌必须看起来能"承重"：可信任、可靠。
- 没有工程师愿意在一个过时、笨重的平台上创造。我们要为一线创造者交付最前沿、且简单上手的技术和工具。

### 两组关键词

| | 关键词 | 画面 |
|---|---|---|
| **可信赖** | 稳定 · 秩序 · 可靠 · 信号 | 冷色调的专业工厂场景，产线与硬件设备精确接入、有序运转。工程师在控制室内监控全局，每一处边缘数据的变化都尽在掌握。品牌绿作为亮点，提示信号。 |
| **年轻前沿** | 前沿智能 · Young tech · 创客 | 明亮的一线操作员工作台与实验室，工具与硬件模块化排布、触手可及。工程师在这里动手搭建、调试、迭代，用代码和 AI 把想法快速变成能跑起来的应用。品牌绿作为点缀与标识色。 |


### 本次重塑的目标

1. 在 Tier0 现有品牌的基础上，凝练并组织品牌故事与设计语言；
2. 建立 AI native 的设计系统，同时服务对外的品牌宣传，以及组织内部的持续维护和交付。

## 2. 设计原则

**Less, but better：优先删减，而非添加**
新增任何颜色、字体或动效，都需要说明它解决了什么问题。界面以中性色为主，品牌色只用在需要引导注意力的位置。克制是可信的前提。

**每个元素都有明确职责**
界面中不存在纯装饰性元素。取景框用于标记焦点，信号点用于表示运行状态，路径用于标识数据位置。职责无法说明的元素，应当移除。

**以真实内容表达**
使用真实的产品界面、设备和数据，不使用象征性的"工业"或"科技"图形，如齿轮、地球连线、发光粒子。文案描述具体能力，避免夸大表述。专业用户对失真的表达高度敏感。

**精确到每一处细节**
间距、对齐、数值格式均遵循规范，发布前不允许存在文字错误。设计不跟随短期视觉潮流。我们的用户会长期使用产品，并以工程标准审视每一个细节。

## 3. 品牌特征

> **控制室里的一盏运行灯：白底黑字、细线分隔的近单色界面，唯有品牌绿亮起的地方，代表数据正在流动。**

Tier0 的界面像一张被精心整理过的工程控制台：白色画布上，浅灰（`#FAFAFA`）托住一块块区域，1px 的细灰线划出边界，带蓝调的近黑（`#050B14`）承担全部文字和主操作。整个界面几乎是单色的，品牌绿（`#B2ED1D`）是品牌层面唯一的颜色：它只出现在需要被注意的地方，比如运行中的状态、实时数据、当前选中项和重点区块，就像设备面板上那盏亮着的运行灯，让每一处变化都"通上了电"。

标题使用 Inter，字形紧凑、字距略收，带来一种工程手册般的确定感；正文使用 IBM Plex Sans，中性、耐读；数据、路径和代码使用 IBM Plex Mono，数字像仪表读数一样整齐对齐。组件刻意保持克制：扁平、几乎没有阴影，4px 的圆角接近直角，边缘利落得像钣金切口。整体氛围是"工程师的工作台"：安静、精确、可靠，相信用户关注的是数据本身，而不是界面的修饰。

选择高饱和的黄绿色，而不是工业软件常见的蓝色，是有意为之。蓝色代表传统、稳妥的"工业 4.0"；而这抹绿介于两种东西之间：一边是设备面板上的运行指示灯，代表"在线、正常、正在工作"；另一边是终端里的光标、荧光笔的标记，带着年轻、前沿、动手的能量。它让一个严肃的工业数据平台，看起来像是一群年轻工程师正在搭建的东西：稳，但不旧。

### 六个特征

| 特征 | 规则 |
|---|---|
| **一盏信号灯** | 品牌绿是品牌层面唯一的颜色，只用于运行状态、实时数据、选中和重点区块；每个区域只有一个绿色焦点。状态色（成功、错误、警告、信息）只在真实结果出现时使用，并配合文字或图标；其他辅助色只出现在图表和分类标签中。 |
| **白底，浅灰托住区块** | 页面以白色为底，卡片区、表格区等大面积区块用浅灰托住；不用彩色大面积背景。 |
| **细线，几乎没有阴影** | 层级由 1px 细线和底色区分；只有下拉、弹窗这类浮层才有极轻的阴影。不用渐变，不用玻璃质感。 |
| **近直角** | 圆角统一 4px，最大不超过 8px；边缘利落，像设备外壳的切口。 |
| **读数一样的数据** | 数字、路径、代码一律使用 IBM Plex Mono，等宽对齐，单位比数值弱一档。 |
| **真实的东西是主角** | 主视觉只用真实的产品界面和设备；它们是页面上唯一"丰富"的内容，周围留白。 |

### 品牌绿怎么出现

品牌绿 `#B2ED1D` 在白底上对比度很低，因此：

- **只以色块、圆点、粗条的形式出现**，上面放近黑文字（`#050B14`）。
- **不用作白底上的文字、细线和图标。**
- 白底上需要绿色识别性的文字、线条、图标或 Logo，改用深绿 `#73B200`。

### 颜色角色

描述和文档中用角色名称呼颜色，代码中用 token 名。

| 角色 | 色值 | Token | 用途 |
|---|---|---|---|
| **Ink** | `#050B14` | `black-900` | 文字、主操作 |
| **Paper** | `#FFFFFF` | `primary-white` | 页面画布、卡片 |
| **Canvas** | `#FAFAFA` | `grey-25` | 托住区块的浅灰 |
| **Hairline** | `#EBEBEB` | `grey-200` | 细线、边框 |
| **Signal** | `#B2ED1D` | `fx-green-500` | 品牌信号 |
| **Deep Signal** | `#73B200` | `fx-green-deep` | 白底上需要绿色识别性的文字、线条、图标、Logo |

### 品牌元素

| 元素 | 样子 | 含义 |
|---|---|---|
| **取景框** | 四角的短线框，框住当前焦点 | 对焦：这里是重点 |
| **信号点** | 品牌绿的小圆点 | 在线、运行中、Agent 在工作 |
| **路径** | `Factory-A / Line-01 / CNC-03`，等宽字体 | 数据有名字、有位置 |
| **读数** | 标签 + 等宽大数字 + 单位，如 `TEMP 72.4 °C` | 实时、可测量 |
| **点阵网格** | 细小的灰色网点，作为背景纹理 | 地基、数据点、图纸感 |

### 为什么这样

| 关键词 | 视觉上的体现 |
|---|---|
| **稳定** | 4px 近直角、扁平无阴影：像设备外壳一样，没有漂浮和晃动感 |
| **秩序** | 白底、浅灰区块、1px 细线：每一块信息都有明确的边界和位置 |
| **可靠** | 近单色、克制、不追潮流效果：不靠装饰说服人，靠精确和一致 |
| **信号** | 品牌绿是品牌层面唯一的颜色：亮起的地方就是需要关注的地方 |
| **前沿智能** | 等宽字体的数据和代码、实时变化的读数：界面本身就是一张运行中的控制台 |
| **Young tech** | 干净的白底、紧凑的 Inter 标题、高饱和的黄绿色：有能量，不沉闷 |
| **创客** | 真实的硬件和界面、路径和代码直接出现在画面里：可以拆开看、可以动手改 |

"可信赖"决定了界面的骨架：白底、细线、直角、无阴影。"年轻前沿"决定了界面的气质：等宽数据、紧凑标题、那一抹高饱和的绿。

## 4. 约束与边界

### 必须

- 所有颜色、间距、圆角、动效都来自 `01-tokens/`，不写硬编码值。
- 主操作使用近黑（`#050B14`），不使用品牌绿。
- 品牌绿只承担两种角色：**信号**（运行、实时数据、选中）、**品牌面**（重点区块的绿色块或浅绿底）；出现形式见「品牌绿怎么出现」。
- 状态同时用颜色和文字表达，不只依赖颜色。
- AI 生成的内容与操作有明确标识。

### 禁止（Anti）

| 类别 | 不使用 |
|---|---|
| 传统工业 4.0 | 蓝色粒子、发光齿轮、地球连线等 |
| 错误的工业感 | 卡通风格、蒸汽朋克、重型机械 |
| AI Slop | 霓虹色渐变、玻璃拟态、复杂层级、emoji 图标 |

另外：图标、箭头、分页圆点不使用品牌绿；只使用规定的字体：Inter、IBM Plex Sans、IBM Plex Mono、IBM Plex Sans SC，Tektur 仅用于 Logo。

### 系统边界

**范围**
- 设计系统负责：Token、产品基础组件、品牌识别与物料、AI 调用规则。
- 设计系统不负责：业务组件、具体页面、产品功能逻辑。

**依赖方向**

```
00-foundation → 01-tokens → 02-components / 03-brand → 04-skills
```

- `02-components` 与 `03-brand` 只引用 `01-tokens`，彼此不互相引用。
- 不跳过 semantic 层直接使用 base token。
- `04-skills` 的参考资料由上游生成，不手写。
