## 1. 品牌故事

### Tier0 是什么

Tier0 为 **制造业** 构建 **Agentic 工业数据平台**。

它让工厂设备和业务系统的数据只需接入一次，就能被语义化集成；让 AI Agent 能在这层数据之上持续地分析、执行和生成应用。

> **Connect once, Reuse everywhere.**

### 故事

每一座工厂里，都有成千上万台设备在不停地产生数据。但这些数据散落在 PLC、MES、ERP 和各种系统里，彼此不通。每做一个新应用，都要重新接一遍；每用一次 AI，都要先花几个月整理数据。

Tier0 把工厂的设备和系统一次接入，按工厂、产线、设备把数据组织好，让每一个数据点都有名字、有位置、有来源、有语义关系。

于是，整座工厂的业务、数据、设备都可以被放进一个平台里。在这个平台上，AI Agent 开始工作：它看得懂工厂，会持续地分析、预警、执行，并生成工厂真正需要的应用。

### 为什么重要

- 没有客户会把整座工厂的数据交给一个看起来不稳定的东西。Tier0 的品牌必须看起来能"承重"：可信任、可靠。
- 没有工程师愿意在一个过时、笨重的平台上创造。我们要为一线创造者交付最前沿、且简单上手的技术和工具。

### 两组关键词

| | 关键词 | 画面 |
|---|---|---|
| **可信赖** | 稳定 · 秩序 · 可靠 · 信号 | 冷色调的专业工厂场景，产线与硬件设备精确接入、有序运转。工程师在控制室内监控全局，每一处边缘数据的变化都尽在掌握。Lime 绿作为亮点，提示信号。 |
| **年轻前沿** | 前沿智能 · Young tech · 创客 | 明亮的一线操作员工作台与实验室，工具与硬件模块化排布、触手可及。工程师在这里动手搭建、调试、迭代，用代码和 AI 把想法快速变成能跑起来的应用。Lime 绿作为点缀与标识色。 |


### 本次重塑的目标

1. 在 Tier0 现有品牌的基础上，凝练并组织品牌故事与设计语言；
2. 建立 AI native 的设计系统，同时服务对外的品牌宣传，以及组织内部的持续维护和交付。

## 2. 设计原则

**Less, but better：优先删减，而非添加**
新增任何颜色、字体或动效，都需要说明它解决了什么问题。界面以中性色为主，品牌色只用在需要引导注意力的位置。克制是可信的前提。

**每个元素都有明确职责**
界面中不存在纯装饰性元素。取景框用于标记焦点，信号点用于表示运行状态，路径用于标识数据位置。职责无法说明的元素，应当移除。

**以真实内容表达**
使用真实的产品界面、设备和数据，不使用象征性的"工业"或"科技"图形，如齿轮、地球连线、发光粒子。文案描述具体能力，避免夸大表述。专业用户对失真的表达高度敏感。

**精确到每一处细节**
间距、对齐、数值格式均遵循规范，发布前不允许存在文字错误。设计不跟随短期视觉潮流。我们的用户会长期使用产品，并以工程标准审视每一个细节。

## 4. 约束与边界

### 必须

- 所有颜色、间距、圆角、动效都来自 `01-tokens/`，不写硬编码值。
- Lime 绿只承担三种角色：**信号**（运行、选中）、**行动**（主按钮，每个视图最多 1 个）、**品牌面**（重点区块的浅绿底）。
- 状态同时用颜色和文字表达，不只依赖颜色。
- AI 生成的内容与操作有明确标识。

### 禁止（Anti）

| 类别 | 不使用 |
|---|---|
| 传统工业 4.0 | 蓝色粒子、发光齿轮、地球连线等 |
| 错误的工业感 | 卡通风格、蒸汽朋克、重型机械 |
| AI Slop | 霓虹色渐变、玻璃拟态、复杂层级、emoji 图标 |

另外：图标、箭头、分页圆点不使用品牌绿；不引入第三种字体（Logo 除外）。

### 系统边界

**范围**
- 设计系统负责：Token、产品基础组件、品牌识别与物料、AI 调用规则。
- 设计系统不负责：业务组件、具体页面、产品功能逻辑。

**依赖方向**

```
00-foundation → 01-tokens → 02-components / 03-brand → 04-skills
```

- `02-components` 与 `03-brand` 只引用 `01-tokens`，彼此不互相引用。
- 不跳过 semantic 层直接使用 base token。
- `04-skills` 的参考资料由上游生成，不手写。
