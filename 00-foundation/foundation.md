## 1. 品牌故事

### Tier0 是什么

Tier0 为 **制造业** 构建 **Agentic 工业数据平台**。

它让工厂设备和业务系统的数据只需接入一次，就能被语义化集成；让 AI Agent 能在这层数据之上持续地分析、执行和生成应用。

> **Connect once, Reuse everywhere.**

### 故事

每一座工厂里，都有成千上万台设备在不停地产生数据。但这些数据散落在 PLC、MES、ERP 和各种系统里，彼此不通。每做一个新应用，都要重新接一遍；每用一次 AI，都要先花几个月整理数据。

Tier0 把工厂的设备和系统一次接入：来自设备的时序数据，和来自 MES、ERP 等业务系统与应用的业务数据，都按工厂、区域、设备、工序、工单统一组织起来，让每一个数据点都有名字、有位置、有来源、有语义关系。接进来的数据长期稳定运行，来源清楚、可以追溯，是客户可以放心依赖的底座。

于是，整座工厂的业务、数据、设备都可以被放进一个平台里。在这个平台上，AI Agent 开始工作：它看得懂工厂，会持续地分析、预警、执行，并生成工厂真正需要的应用。

我们相信，一线的工程师和 builders 应该用上最前沿的技术，而且即开即用，而不是在过时、笨重的平台上创造。Tier0 为工厂提供稳定、可信赖的数据平台，也为创造交付简单上手的工具。

### 为什么重要

- 没有客户会把整座工厂的数据交给一个看起来不稳定的东西。Tier0 的品牌必须看起来能"承重"：可信任、可靠。
- 没有工程师愿意在一个过时、笨重的平台上创造。我们要为一线创造者交付最前沿、且简单上手的技术和工具。

### 两组关键词

| | 关键词 | 画面 |
|---|---|---|
| **可信赖** | 稳定 · 秩序 · 可靠 · 信号 | 冷色调的专业工厂场景，产线与硬件设备精确接入、有序运转。工程师在控制室内监控全局，每一处边缘数据的变化都尽在掌握。品牌绿作为亮点，提示信号。 |
| **现代前沿** | 前沿智能 · Young tech · 创客 | 明亮的一线操作员工作台与实验室，工具与硬件模块化排布、触手可及。工程师在这里动手搭建、调试、迭代，用代码和 AI 把想法快速变成能跑起来的应用。品牌绿作为点缀与标识色。 |


### 本次重塑的目标

1. 在 Tier0 现有品牌的基础上，凝练并组织品牌故事与设计语言；
2. 建立 AI native 的设计系统，同时服务对外的品牌宣传，以及组织内部的持续维护和交付。

## 2. 设计原则

**Less, but better：优先删减，而非添加**
只加入能解决问题的颜色、字体和动效。品牌色留给关键状态与操作。

**每个元素都有明确职责**
方块标记状态与要点，层级树标数据路径。无明确用途的元素应移除。

**以真实内容表达**
展示真实界面、设备和数据；用具体文案说明能力。

**精确到每一处细节**
统一间距、对齐和数值格式，发布前检查每处文字。

## 3. 品牌特征

> **工业控制室里的一盏运行灯：白底黑字、细线分隔的近单色界面，唯有品牌绿亮起的地方，代表数据正在流动。**

Tier0 的界面以白色为底，浅灰（`#FAFAFA`）区分区块，1px 细线划定边界，近黑（`#050B14`）用于文字和主操作。界面整体接近单色，品牌绿（`#B2ED1D`）只出现在运行状态、实时数据、选中项和重点区块上，用来标记正在发生的变化。

标题使用 Inter，字形紧凑、字距略收；正文使用 IBM Plex Sans；数据、路径和代码使用 IBM Plex Mono，数值等宽对齐。组件扁平，层级以细线为主，阴影只用于浮层和交互反馈；圆角以 4px 为主。

整体气质是稳定、精确的工程控制台，同时带有年轻现代、前沿智能的技术感：亮绿色的品牌绿、等宽字体的代码与数据、路径和连线等工程元素，让界面像一个正在运行、可以动手搭建的系统，而不是传统的工业软件。

### 特征

| 特征 | 规则 |
|---|---|
| **信号灯** | 品牌绿是品牌层面唯一的强调色，用于运行状态、实时数据、选中和重点区块，让需要关注的地方一眼可见。状态色（成功、警告、错误、提示）不属于品牌色，只用于表达真实的结果；辅助色只用于图表和分类标签。 |
| **白底，浅灰区块** | 页面以白色为底；官网的卡片区用浅灰托住，产品里的表头和悬停行用浅灰填充。白与浅灰两层就能分出区域，不需要额外的颜色，界面保持干净，让品牌绿和数据更容易被看到。 |
| **细线为主** | 页面内的层级以 1px 细线为主，细线让每块信息的边界明确、结构一目了然，接近工程图纸和设备面板的秩序感。浅灰填充和阴影是补充：表头、悬停用浅灰，浮层和需要与背景区分的面板可以用阴影。 |
| **近直角** | 圆角以 4px 为主，卡片 6px，最大不超过 8px；胶囊徽章、进度条、开关、头像等本身是圆形的元素除外。接近直角的边缘显得利落、精确，符合工业设备和工程工具的气质；统一的小圆角也让组件之间更整齐。 |
| **产品本身就是展示** | 画面以产品为主：真实的界面、操作过程和可交互的演示，让用户直接动手、直接体验，从而建立信任、快速上手。辅助画面只用来说明产品的关键概念，层级简单清晰，一个画面只讲一件事。 |
| **工程气质** | 用工程图纸和数据结构里的元素组织画面：层级树代表 UNS 的数据组织方式，连线架构图和等距方块插图说明数据接入与关键概念，方块标记代表状态与要点，代码与命令用等宽字体，点阵作为背景，带来图纸般的秩序感。 |

## 4. 约束与边界

### 约束

- 颜色、字体、间距、圆角、动效都来自 `01-tokens/`。
- 具体使用规则写在各模块中：颜色与字体见 `01-tokens/README.md`，组件见 `02-components/`，品牌物料见 `03-brand/`。

### 禁止（Anti）

| 类别 | 不使用 |
|---|---|
| 传统工业 4.0 | 蓝色粒子、发光齿轮、地球连线等 |
| 错误的工业感 | 卡通风格、蒸汽朋克、重型机械 |
| AI Slop | 霓虹色渐变、玻璃拟态、多层嵌套的卡片、emoji 图标 |

### 系统边界

**范围**
- 设计系统负责：Token、产品基础组件、品牌识别与物料、AI 调用规则。
- 设计系统不负责：业务组件、具体页面、产品功能逻辑。

**依赖方向**

```
00-foundation → 01-tokens → 02-components / 03-brand → 04-skills
```

- `02-components` 与 `03-brand` 只引用 `01-tokens`，彼此不互相引用。
- `04-skills` 的参考资料由上游生成，不手写。
