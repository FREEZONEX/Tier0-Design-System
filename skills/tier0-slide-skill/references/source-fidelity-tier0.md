# 源稿保真与排版质量（Source Fidelity）

适用于：**优化 / 重排已有 PPTX**、用户明确「内容不变」「视觉优化」「不要丢页」。

**先判模式，再动手。** 源稿若已有完整素材、图片与可用布局，默认走 **模式 A · 风格统一**——只按 Tier0 `DESIGN.md` / `tokens/deck.css` 收字体、颜色、边框、圆角与少量对齐；**禁止**整页推翻重排。只有布局明显失败或用户明确要求重构时，才进入模式 B。

用对了 `template-tier0.html`（底栏圆点 / 右侧翻页 / ESC 总览）只是最低门槛；**标题、层级、主图、Demo 槽、素材角色**任一失控 = 失败，必须返工。

本文件优先于「为了好看而压缩页数」「用脚本批量灌版」或「套 Gallery 把好稿拆乱」的冲动。

---

## 模式选择（必须先写进工作备注）

| 模式 | 何时用 | 允许做什么 | 禁止做什么 |
|------|--------|------------|------------|
| **A · 风格统一（默认）** | 源页构图清楚：分区、主图位置、文案块已成立；用户说「优化细节 / 统一风格 / 内容不变 / preserve」 | 换字体栈与字重阶梯、换色到 Tier0 token、发丝边框、圆角收敛、微调间距/对齐、修对比度；封面/封底可套统一语法 | 打散重排、改列数/主从关系、把图挪到别的语义槽、删图、用无关素材填空、为「更像 Gallery」重做信息架构 |
| **B · 结构重排** | 源页破碎/挤角/空壳 Demo、标题碎片、或用户明确 `adaptive` / `rebuild` /「重新排版」 | 在保真页数与素材前提下，按该页 `purpose/coreClaim` 选 Gallery 语法重排 | 仍禁止少页、丢素材、假保真批量同壳 |

**判定口诀：** 若去掉颜色字体后，源页结构仍能讲清故事 → **模式 A**。若结构本身读不通 → **模式 B**，且只修读不通的那几页，不要株连整套。

intake `narrative.sourceTreatment`：

- `preserve` / `source-faithful` → **默认模式 A**  
- `adaptive` → 事实锁定，可对失败页做局部模式 B  
- `rebuild` → 允许模式 B，但仍 页数协商 + 素材不丢

## 硬规则 A · 保真（页与素材）

1. **页数 1:1** — 源 N 页则交付 N 页；删/并页必须用户书面批准。  
2. **素材不丢失、不乱用** — 插图/配图/截图/视频抽出后挂回**原语义页**；禁止把 A 页图塞进 B 页「凑版面」；禁止小 icon 当 hero。  
3. **禁止用 dual 8 kind 压长稿** — 富媒体长稿走 template +（模式 B 时）Gallery 语法。  
4. **「内容不变」** — 模式 A 只动视觉 token；不可改结论、删案例、删图、改数字、乱拼标题。  
5. **省略可审计** — `content-coverage.json`；未批准不得排除。

## 硬规则 A2 · 模式 A 的具体动作（DESIGN.md / deck token）

对照仓库根目录 `DESIGN.md`、`tokens/deck.css`、`references/tier0-vi-style-guide.md`：

| 维度 | 统一到 |
|------|--------|
| 字体 | 白底正文/标题 IBM Plex Sans；mono 标签 IBM Plex Mono；深墨章节巨标题可用 Tektur **全大写** |
| 颜色 | 纸白 / 墨黑；绿 `#B2ED1D` 只作信号（底/条/点），白底可读强调用深绿 `--accent-text` / `--accent-text-dark`，禁止白底亮绿字 |
| 边框 | 1px 发丝 `--border-subtle`；少用粗框、双线、装饰描边 |
| 圆角 | 默认克制/近直角（跟 template）；不要随意 `rounded-2xl` / 胶囊堆 |
| 阴影 | 默认无重阴影；证据图可用极弱描边 |
| 间距 | 可微调对齐与疏密，**不改**源页分区骨架（几栏、谁左谁右、主图在哪） |

**固定统一页（模式 A 也允许替换语法）：**

- **封面** → `TIER0-COVER-EDITORIAL`（保留源标题/副文案/主视觉意图）  
- **封底** → `TIER0-CLOSING-SPLIT`（按 intake 决定 QR）  
- **深墨章节分隔**（若源已有）→ 保持「一句主张」结构，套 `ink-section-divider` 视觉  

其余正文页：**先描摹源构图**，再刷 token；不要先选一个 `Sxx` 再往里塞。

## 硬规则 B · 排版质量（模式 B / 失败页专杀）

对照用户拒收的典型坏例：**字忽大忽小、大片留白无重点、图标乱飞、Demo 黑块+碎图、标题念不成句、封面语法错、PPTX 像草稿、好稿被推翻后乱七八糟。**

### B1. 标题必须可读成句

PPTX 解包出的 `<a:t>` 常常是碎片段（`Why` / `IR4.0` / `and … Fail`）。

- **禁止**把第一个碎片直接当 `h1`（会出现整页标题只有 “Why”）。  
- **必须**按阅读顺序拼回完整标题，再与源页截图/缩略目视核对。  
- 副标题、kicker、正文分层：kicker ≤ 14px meta；主标题一页一句；正文可读（投屏距离）。  
- 禁止标题里重复词（如 `Notebook · Notebook ·`）。

### B2. 媒体必须分角色，禁止「凡图必贴」

解包 `ppt/media/*` 后先分类，再排版：

| 角色 | 判定（经验阈值） | 用法 |
|------|------------------|------|
| **hero** | 通常 ≥ ~80KB，或明显的架构图/产品截图/场景图 | 本页唯一主视觉，占证据槽最大面积 |
| **poster** | 与视频成对的静帧 | Demo 页视频封面 |
| **chrome-icon** | 往往 &lt; ~15KB 的 png/svg 小标 | 只作列表/步骤旁小图标，**禁止**当主图、禁止放大铺满 |
| **video** | mp4/mov | Demo 页主证据；HTML `<video controls>`；PPTX 用 poster + 可编辑说明 |

- 一页 **最多一个 hero**。多个大图用并排/网格，但总面积要撑满证据区，不要缩成右上角邮票。  
- **禁止**把一堆小 icon 与 hero 并列导致「图标乱放」。  
- 源页若是全出血图/视频：证据区应接近满高（S15/S16），左侧文案栏变窄或改为底栏 caption，**禁止**左侧大黑空块 + 右侧碎图。

### B3. Demo / 视频页（S16）

源页几乎只有视频或「屏中屏」时：

1. 主区域 = 视频（或 poster）**铺满证据槽**，圆角 + 细边框即可。  
2. 标题用源页真实产品名/任务名，**禁止**整页主标题写死 `DEMO`。  
3. 不要为「看起来有布局」硬塞左栏空洞黑矩形。  
4. 连续多页 Demo 允许同一语法，但每页 hero 必须是**该页自己的**视频/截图，且标题区分任务。

### B4. 封面（必须 `TIER0-COVER-EDITORIAL`）

- 左：品牌 kicker + **完整主标题**（可两行）+ 一句 side note；有 speaker/date 才显示。  
- 右：亮绿 ASCII 点阵场 **或** 源封面主视觉（一张 hero），二选一作主锚，不要又叠碎 icon。  
- **禁止**示例模板里的 `[必填]` 占位残留、accent 满屏绿封面误用、主标题语法被拆碎。  
- 打开 `layout-gallery` / `components-tier0.md` 的 COVER-EDITORIAL 对照后再写。

### B5. 信息层级与疏密

- 每页先写 `purpose / coreClaim / heroElement`，再动 HTML。  
- 主标题、结论、hero 图必须在 5 秒内扫到；禁止「标题巨大、正文蚂蚁字、中间空白」。  
- 三卡/四列时卡片等高、字号统一；禁止一列塞满另一列空场。  
- 对照 `layout-first-principles-tier0.md` + `layout-density/` 疏密参考。

### B6. 禁止的「假保真」生成法

以下做法**明确禁止**（即使页数=N、媒体文件都在磁盘上）：

1. 用通用脚本按 `shape=video|text` 套同一 HTML 壳，不看源页构图。  
2. 按文件名顺序把该页所有 media 塞进 grid，不区分 icon/hero。  
3. 标题取 `texts[0]` 碎片。  
4. PPTX 用「左大段 bullet + 右贴一张图」流水线生成全部页面，无层级。  
5. 只换 template 壳子、不对照源 PPT 逐页目视验收。  
6. **源稿布局本已完整，却整套按 Gallery `Sxx` 推翻重排**（模式 A 误用成模式 B）。

合格路径：

- **模式 A：** 对照源缩略描摹分区 → template 壳 → 只刷 token；封面/封底统一语法。  
- **模式 B：** 对照源缩略判定版式家族 → 借用 Gallery 骨架 → 填入校对标题与分类 media → 目视验收。  
两种模式都禁止批量同壳、禁止跨页乱用素材。

## 优化已有 PPTX 的标准流程

```text
1. 解包 → N 页、文字 runs、media（含字节数）+ 每页缩略/构图笔记
2. 判定整套默认模式 A 或 B；对明显失败页单独标 B
3. 抽出 media；标注 hero / icon / video / poster；素材只回原页
4. source-outline.json：完整标题、coreClaim、模式(A/B)、是否动结构
5. 模式 A：描摹源构图 → 套 template 壳 → 只刷 DESIGN.md / deck token
   模式 B：选 Gallery 语法 → 填校对标题与分类 media
6. 封面/封底按统一语法（保留源文案与主视觉意图）
7. content-coverage.json：N/N
8. ESC 总览：模式 A 页应「一眼仍是原稿结构」；模式 B 页无空壳/碎图
9. 再导 PPTX（可编辑标题/正文 + 原 hero）
```

## 交付前总览验收（ESC / 缩略图）

在 template 按 `ESC` 看全局，**任一勾不上就返工**：

- [ ] 页数 = 源页数  
- [ ] 模式 A 页：与源缩略对比，分区/主图位置基本一致（不是换了一套乱版）  
- [ ] 无「只有 Why / DEMO」这类残缺主标题  
- [ ] 无整页大面积无意义空白（内容挤角落）  
- [ ] 无小 icon 充当主图、无碎图邮票墙、无跨页乱用素材  
- [ ] Demo/视频页主证据铺满，标题为任务名  
- [ ] 封面 `COVER-EDITORIAL`、封底 `CLOSING-SPLIT`，无模板占位符  
- [ ] 字体/色/边框/圆角已落在 Tier0 token（对照 DESIGN.md / deck.css）  
- [ ] PPTX 抽查：标题可编辑、hero 图在、不是纯流水账

## HTML 壳 vs 内容质量

| 已具备（不够） | 仍必须合格 |
|----------------|------------|
| template 底栏圆点 / 右侧翻页 / ESC 总览 | 标题完整、层级清楚 |
| 16:9 canvas-card | hero 图正确且够大 |
| 页数 1:1 | Demo/封面/对比页各用对语法 |

## 与 dual builder

- 绿场短稿：可用 dual starter。  
- 富媒体长稿优化：**禁止**dual kind 天花板；HTML template 为主；PPTX 为可编辑伴侣，质量同样受 B1–B6 约束。
