# 交付套件

让原型能被评审和开发「用」起来的四个部件。都不属于产品界面，样式用 token，但文案用中文。

## 1. 原型控制（右下角）

**位置**：`position: fixed; right/bottom: calc(16px + env(safe-area-inset-*))`。层级在弹窗遮罩（z-50）之上、交付说明抽屉（z-60）之下，弹窗打开时也能切换。

**结构**：

```
┌ [原型] Plan & Billing · 开发交付        ⌄ ┐  ← 标题 + 收起
│ 角色        [Owner | Builder]            │
│ 场景        [Active | Trial | 额度用尽 | 新空间] │
│ 已绑卡      [是 | 否]                     │  ← 关键开关，分段按钮
│ 待移除席位  [无 | 1 个]                   │
├──────────────────────────────────────────┤
│ [弹窗直达 ⌃] [组件标注]        [交付说明] │  ← 弹窗菜单向上展开
└──────────────────────────────────────────┘
收起后：一个圆角胶囊「原型 原型控制 ⌃」
```

- 宽 340px（流程原型 300px），`max-width: calc(100vw - 32px)`
- 手机宽度默认收起；页面底部留白 ≥ 面板高度，最后的卡片能滚到面板上方
- 场景切换要重置相关状态（如切到 Trial 时清掉待移除席位、离开 Billing tab）
- 「弹窗直达」列出每个弹窗和它的变体（如 Add Seats · 优惠码生效 / 无效 / 价格加载失败 / 绑卡回跳），外加「Toast 示例」
- 流程原型（形态 B）额外放：界面语言、跳到步骤、当前步骤说明、提交载荷预览

`<details class="proto">` 或 JS 状态 `S.panelOpen` 都可以；用 JS 时把开关状态和角色、场景、tab 一起存进 `localStorage`（读写包 try/catch）。

## 2. 组件标注

每个组件根节点输出三个属性：

```js
const meta = (component, src, props = '') =>
  `data-component="${esc(component)}" data-src="${esc(src)}"${props ? ` data-props="${esc(props)}"` : ''}`;

// 用法
`<div ${meta('CnProgress', 'packages/ui/components/cn-progress.tsx', 'value={60} color="bg-warning"')} …>`
```

命名约定：
- 复用组件写组件名：`Button`、`CnDialog`、`CnTabs`
- 改造的业务组件写组件名 + 文件：`BuilderSeatsCard` → `…/plan/builder-seats-card.tsx`
- 新增写 `（新增）` 并给出建议路径：`SegmentedProgress（新增）` → `…/plan/segmented-progress.tsx`
- 外部库写库名：`Ant Design RangePicker（样式覆盖）`
- 既有外壳写 `（既有，非本次范围）`

**标注模式**：body 加 `.inspect` 后虚线框出所有 `[data-component]`；`mousemove` 找最近的 `[data-component]`，在指针旁显示浮层：组件名（蓝）、props（等宽）、路径（灰）。

## 3. 交付说明抽屉

右侧滑出，宽 `min(640px, 100vw)`。固定五节，内容是给开发的：

| 节 | 内容 |
|----|------|
| 怎么用这个原型 | 原型控制在哪、组件标注怎么开、主稿与旧版弹窗分别对应哪个 Figma 节点 |
| 文件与改动范围 | 表格：区域 · 文件 · 类型（复用 / 改造 / 新增，用 success / warning / blue 三色小标签）· 说明。路径前缀单独写一行 |
| 状态与规则 | 状态矩阵：每个角色 / 场景 / 边界态的表现 |
| 需产品 / 后端确认 | 编号列表：Figma 内部不一致、Figma 与代码不一致、价格与口径、缺失的接口 |
| i18n | 表格：用途 · key · 状态（新增 / 改文案 / 已有）。注明写入的模块文件路径和「中文用你」 |

写「待确认」的标准：会让开发写错或返工的点。不写已经确定的事，不写设计偏好。

## 4. 示例数据

- 数据集中定义在脚本顶部（`SCENARIOS`、`MODULES`、`USERS`），每个场景一份
- 同一个数字在不同位置必须一致：页面多处引用的总量、已用、重置日从同一个函数算
- 时间序列按日期确定性生成（哈希），切换时间范围时同一天数值不变
- 「今天」写成常量，所有相对日期（剩余天数、重置日）从它算
- 价格、口径来自旧版稿或代码时注明来源；不确定写进「待确认」

## 5. 交互链路

至少走通这些，带 loading 和结果反馈：

| 链路 | 做法 |
|------|------|
| 提交类弹窗 | 按钮 loading 800–1000ms → 关闭弹窗 → Toast → 页面数据更新 |
| 二次确认 | 第一个弹窗的数据带进确认弹窗（数量、优惠码、金额） |
| 外部跳转（Stripe、Members 页） | Toast 说明将跳去哪里，不真的跳 |
| 绑卡回跳 | 模拟回来后自动打开原弹窗，并显示「已保留你的选择」提示 |
| 撤销类 | 页面上的提示条或行内按钮直接撤销 + Toast |
| 输入校验 | 回车或失焦校验；成功 / 失败图标在输入框右侧，错误文案在下方 |
